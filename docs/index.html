nvim‑config

A LazyVim configuration for day-to-day coding — file explorer, command palette, debugger, source control, minimap, all in Neovim.

Install → Jump to keymaps
01

Overview

This is a personal LazyVim configuration: a fixed IDE-style layout (explorer left, outline right, diagnostics and tasks along the bottom), a command palette, a debugger, a source-control panel, and a minimap — all reachable through the keymaps in §04.

02

Requirements

Neovim itself, plus the usual LazyVim toolchain. Language-specific runtimes are only needed for the languages you actually touch.

ToolWhy
Neovim ≥ 0.10Base editor. This config tracks current stable Neovim.
GitPlugin management via lazy.nvim, and the Neogit/Diffview/gitsigns stack.
A Nerd FontIcons in the explorer, statusline, minimap, and breadcrumbs. Boxes instead of glyphs almost always mean this is missing.
ripgrep + fdBacks fzf-lua's file and live-grep pickers.
nodeSeveral LSP servers (vtsls, marksman, etc.) and CopilotChat's tokenizer build step.
python3Needed for pyright/ruff tooling and any Python project you open.
make + C compilerTreesitter parser builds, CopilotChat's make tiktoken.
03

Install

Back up any existing config, then clone this one into the standard Neovim config path:

mv ~/.config/nvim ~/.config/nvim.bak 2>/dev/null
git clone https://github.com/zangjiucheng/nvim-config.git ~/.config/nvim
nvim

First launch bootstraps lazy.nvim, installs every plugin, and pulls in LSP servers/formatters/debug adapters through Mason. It'll take a minute — let it finish, then restart Neovim once.

Verify it worked: run :checkhealth and :Lazy. If icons render as boxes, your terminal font isn't a Nerd Font — swap it and reload.
tmux users: this config's tmux prefix is expected to be Ctrl+S, which is why saving lives on Alt+S instead of the LazyVim default Ctrl+S — see Global keymaps.
04

05

Architecture

LazyVim base + extras provide the substrate (LSP, Mason, formatting, linting, completion, treesitter). These files are the entire custom layer on top:

lua/config/
  options.lua  # globals, formatting/UI defaults, autoformat off by default
  keymaps.lua  # VS Code-style shortcuts, workflow key groups
  autocmds.lua# colorcolumn highlight
  ide.lua      # project/venv/package-manager detection helpers
lua/plugins/
  ui.lua       # theme, breadcrumbs, sticky scroll, minimap, swatches
  navigation.lua# motions, outline, buffer cycling, LSP peek
  editor.lua   # LSP/treesitter folding
  git.lua      # gitsigns, Diffview, Neogit source-control panel
  workflow.lua  # sessions, projects, tasks, tests, debugging
  languages.lua # Python/JS-TS support, Jupytext, LaTeX
  ai.lua       # Copilot core + chat sidebar
  other.lua    # wakatime
06

Remote & multi-root

Neither gets a dedicated plugin — both lean on plain Neovim primitives to stay dependency-free.

Remote development

<leader>pR prompts for a host and opens ssh <host> in a floating terminal, running your remote box's own Neovim. This is not a local-UI-drives-remote-backend setup the way VS Code Remote-SSH is — it's the lightweight, dependency-free answer. Pair it with tmux on the remote side to keep sessions alive across disconnects.

Multi-root workspaces

<leader>pt opens a new tab, lets you pick from project.nvim's recent-projects list, runs :tcd scoped to that tab, and opens the explorer there. Each tab becomes its own workspace root — switch tabs (gt / gT) to switch "workspace." <leader>pp still does a plain single-window project switch when a separate tab isn't worth it.

07

External tools

Mason installs most editor-side tooling automatically, but these still need to exist in the project or environment.

LanguageNeeds
Pythonpytest for tests, plus a project interpreter/virtualenv (.venv/venv auto-detected)
JavaScript / TypeScriptjest and/or vitest in the workspace for neotest adapters
DebuggingMason-managed debugpy and js-debug-adapter; tsx or ts-node to launch TS files directly

dap.continue() picks up .vscode/launch.json automatically when present, so existing project launch configs stay first-class. Overseer also surfaces npm, task, make, and .vscode/tasks.json alongside its own lightweight Python/Node templates.
